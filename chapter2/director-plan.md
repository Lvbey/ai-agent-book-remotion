# 《上下文工程》导演策划与知识映射（完整章节教学版）

## 制作目标

这不是“上下文工程是什么”的短科普，而是将指定章节改编为一堂可独立学习的动画课。验收问题不是“画面是否漂亮”，而是观众能否解释每个机制的输入、处理、输出、失败模式与工程取舍。

**核心观点：上下文工程不是堆提示词，而是在每个决策点，把任务所需的正确、相关、可信的信息，以合适的结构和成本交给模型。**

原文：[AI Agents in Depth · 第二章《上下文工程》](https://github.com/bojieli/ai-agent-book/blob/main/book/chapter2.md)。已读取章节全文（约 61,756 字符）。视频不会逐字朗读整章，而是通过可视化教学覆盖全章核心机制、关键实验结论和工程边界。

## 教学承诺

看完后，观众应能解释上下文如何影响 Agent；读懂 system/user/assistant/tool 消息与独立 tools 定义；复述模型请求工具、框架执行、结果回填的完整循环；理解 Chat Template、token 序列、KV Cache 与 Prompt Cache；组织系统提示词、Few-shot 和工具描述；区分 Skill、工具能力和不可信外部内容；理解状态栏的字段、位置与可靠性风险；区分上下文溢出与 Context Rot；比较六类压缩策略、生产分层压缩和子 Agent 隔离。

## 故事主线

以“Agent 修复支付回调 Bug”为贯穿案例：缺少背景导致错误修改；补齐 API 消息、工具调用与项目规范后，任务变得可控；工具历史增长后，再用缓存、状态栏、压缩与子 Agent 隔离解决信息成本。时间/天气示例用于解释独立工具并行调用；压缩实验用原文数据并明确其特定实验边界。

## 技术边界

动画中的支付代码、日志和状态是教学虚构例子；压缩实验数据来自原文特定实验，不能当成普遍性能承诺。上下文不会改变模型参数；它影响推理时可用的信息。KV Cache 与 Prompt Cache 的命名和行为随服务实现变化。压缩是有损提炼，保留来源提高可追溯性但不保证摘要完整。提示注入防护需要结合权限、参数验证与执行层控制。“上下文学习本质上是检索而非推理”应呈现为原文作者的分析框架，而不是已解决的学界定论。
