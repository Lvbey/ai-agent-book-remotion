## 一、链路

```
src/data/units/s0~s9.json            口播稿（148 语义单元，唯一文案源）
        │
        ├─ scripts/tts-synthesize.py       逐单元合成 → narration/ep01/segments/<ID>/
        │                                  audio.wav / audio.raw.wav / words.json / manifest.json
        │                                  → narration/ep01/audio-index.json
        │
        ├─ scripts/build-subtitles.mjs     真实时长 → 单元帧长；字级时间戳 → 字幕区间
        │                                  → src/data/ep01-units|captions|meta|narration.generated.json
        │
        ├─ scripts/build-narration-track.mjs  采样级帧对齐拼接 → master.wav → public/…/ep01-narration.mp3
        │
        └─ src/Ep01.tsx                     <Audio> 挂载整轨；审核标识切换为「配音版 · 真实语音」
```

设计要点：

1. **逐单元合成而非整段合成**：148 个单元各自音频、各自字级时间戳，任一文案改动只需重合成该条（内容哈希缓存，其余不重复计费）。
2. **采样级帧对齐**：48000 Hz ÷ 30 fps = 1600 samples/帧，单元音频精确落在 `startFrame × 1600` 采样点，1680 秒全片不累积偏移。实测最大插入间隙 11120 samples（0.23s，含 0.2s 呼吸停顿与整帧取整）。
3. **静音归一化**：provider 句末附带约 0.9 s 静音，逐单元拼接会累积成明显拖沓。按 **10 ms 能量包络**定位真实收声边界，裁到「首字前 100 ms ~ 收声后 220 ms」，切口两端各做 20 ms / 12 ms 淡入淡出。气口交给时间轴常量控制，实测节省约 1.4 分钟无效静音。
4. **不做「半真半估」的时间轴**：音频索引不完整时构建脚本直接失败，避免一部分单元用真实时长、一部分用估算时长。

### 7.2 渲染中发现并修复的两处缺陷

**（1）短字幕条导致渲染硬失败**

初次全片渲染在第 24,052 帧崩溃：`inputRange must be strictly monotonically increasing but got [0,5,3,8]`。

根因在 `src/components/ui.tsx` 的 `Subtitle`：淡入淡出区间按字幕时长构造 `[0, 5, len-5, len]`，当 `len ≤ 10` 帧时区间退化（`len=8 → [0,5,3,8]`，`len=10 → [0,5,5,10]`），Remotion 直接抛错。阶段 A 的估算时码下没有 ≤10 帧的字幕条，真实语音时码让 `EP01-U070-C03`（「变。」8 帧）与 `EP01-U070-C06`（「、」10 帧）落到该区间，缺陷才暴露。

修复：`len ≤ 10` 时字幕常显（`opacity=1`），不再构造区间。两处帧号已单独出图验证。

**（2）整轨响度偏低 3 dB 且响度不足**

对比发现整轨 MP3 峰值 -2.79 dBFS，成片中却是 -5.81 dBFS，差值恰好 3.01 dB。经同段对比测试确认为 ffmpeg 等功率声像定律（1/√2）在**单声道 → 立体声上混**时的固有衰减，Remotion 音频管线同样如此。同时整片集成响度仅 -23.4 LUFS（取 60 秒语音密集区单独测量亦为 -23.4 LUFS，说明是语音本身偏轻，非静音间隙导致），低于网络播放常见目标。

修复（`scripts/build-narration-track.mjs`）：

- 整轨改为**立体声**输出（`-ac 2`），不再依赖下游上混行为；
- 编码前做**两遍 loudnorm**（目标 `I=-18 LUFS / TP=-1.5 dBTP / LRA=11`），并把编码后实测响度与真峰值写入 `master.manifest.json`；
- 增加闸门：成品响度偏离目标 >1.5 LU 或真峰值 >-0.5 dBFS 时直接 FAIL。

重建后整轨 **-23.3 → -18.2 LUFS**（真峰值 -4.8 dBFS）。由于该修正只涉及音频，成片采用「视频流复制 + 新音轨重封装」落地，避免再花约 45 分钟重渲：

```bash
ffmpeg -i out/EP01-voiced.renderonly.mp4 -i public/narration/ep01-narration.mp3 \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 256k -ar 48000 -ac 2 \
  -t 1787.4 -movflags +faststart -y out/EP01-voiced.mp4
```

今后直接 `npm run narration:build && npm run render:voiced` 即产出同等响度的成片，无需手工重封装。

**（3）17:04 处 3 秒画面停滞**

首次成片跑 `check-visual` 报 1 处非预期停滞：17:04–17:06（`CodeState` / S5 / `EP01-U087`），运动量 0.064–0.08，低于 0.1 判定线。

根因：`CodeState` 的代码面板只在「未打完」时显示闪烁光标（`{!done ? 光标 : null}`）。U087 的代码行在第 3 秒就打完了，而下一条结果块在第 6 秒才入场，中间 3 秒面板完全静止，画面里只剩底部字幕在换行。阶段 A 的估算时码较短，这个空档不足 3 秒，所以此前未触发。

修复（`src/scenes/CodeState.tsx`）：面板内加一条 3px 高、低透明度的绿色扫描光带（`flowPhase(frame, 96)` 循环下移），既保证空档期有持续可见推进，也贴合「确定性函数 / 可验证介质」的语义。改动前该区间运动量 0.06，改动后 0.57。

局部验证方式：单独渲染 `--frames=30660-30810`，按与 `check-visual` 相同的口径（@10fps → 224×126 灰度 → 9 个差分求和）复算每秒运动量，确认达标后再重渲全片。

## 八、阶段 D：尾音被截断的修复

### 8.1 现象

成片中出现多处「音频戛然而止、最后一个字没说完」，用户指出的三处为 9–10 s「记住知识」的「识」、22 s「需求」的「求」、2:22「长期信息」的「信息」。

### 8.2 根因

切口是按**字级时间戳**算的：`end = words[-1].endTime + 0.25`。但 provider 返回的末词 `endTime` 普遍**早于真实收声**，而原始音频句尾静音只有 0.4 s 左右，于是「末词时码 + 0.25 s」经常落在真实语音内部，把尾音直接切掉。

用 `scripts/tts-boundary-probe.py` 对 `EP01-U001` 做原始音频取证：

| 指标 | 值 |
| --- | --- |
| 原始音频总长 | 10.782 s |
| 末词「识。」provider 时码 | 9.875 s 结束 |
| 实际收声（能量包络） | 到 **10.350 s** |
| 时码滞后量 | **+0.475 s** |
| 原始尾部静音 | 0.432 s |
| 旧裁切点（9.875 + 0.25） | 10.125 s → **切掉 0.225 s 真实语音** |

同时验证了时码本身没有整体漂移：以音频内部停顿位置对时码做最小二乘缩放，最佳缩放 **1.002**、平均对齐误差 50 ms，说明只是**末词时码未覆盖收尾**，不需要校正字幕时码。

**影响面（修复前 148 段全量统计）：**

| 指标 | 值 |
| --- | --- |
| 末词时码早于真实收声的单元 | **104 / 148** |
| 被截掉的语音总量 | **38.8 s** |
| 单段缺失中位数 / 最大 | 0.31 s / 1.53 s |
| 最后一个有声点距结尾 < 0.12 s 的段 | 88 |
| 结尾 10 ms 残留能量 > 5% 峰值的段 | 66（> 15% 的 34 段） |

### 8.3 修复

`scripts/tts-synthesize.py` 的分段格式升到 `format 4`，切口改为**按能量包络**而非按字级时码：

- 10 ms 窗计算 RMS 包络，阈值取 `max(峰值 × 0.02, 48/32768)`（约 -34 dBFS，并有绝对下限防底噪误判）；
- 起点 = 首个过阈窗 - `LEAD_PAD_SEC(0.10)`，终点 = 最后一个过阈窗 + `TAIL_PAD_SEC(0.22)`；
- 两端分别做 20 ms / 12 ms 淡入淡出。头部之所以要 20 ms：148 段里有 53 段 provider 原始音频的 `t=0` 就是满幅起音（`trimOffset=0`，不是我们切掉的），硬起音会有爆音风险；
- 每段把 `speechStartSeconds` / `speechEndSeconds` / `edgeEnergyRatio{head,tail}` / `rawDurationSeconds` / `trimOffsetSeconds` 写入 manifest，供回归校验；
- 保留 `audio.raw.wav`，因此**格式升级后直接本地重裁**（`format` 不匹配即触发），无需重复调用 API，148 段重裁 0 次网络请求、0 次重合成。

**修复后全量复核：**

| 指标 | 值 |
| --- | --- |
| 尾部残留能量 | 最大 **0.63%** 峰值（上限 3%），0 段越线 |
| 头部残留能量 | 最大 26.1%（上限 35%），0 段越线 |
| 尾气口 | 统一 0.220 s |
| 语音总时长 | 1,755.5 → **1,789.5 s**（补回 34.0 s，与 38.8 s 缺失量的差值来自 0.22 s 统一气口） |
| 时间轴 | 53,622 → **54,637 帧**（30:21.23） |

### 8.4 回归防线

- `check-narration.mjs` 新增切口闸门：任一段 `edge.tail > 3%` 或 `edge.head > 35%` 直接 FAIL；缺 `edgeEnergyRatio` 字段则提示重跑 `narration:synth` 触发重裁。
- `tts-selftest.py` 的裁剪用例按新语义重写，核心回归是「末词时码早于真实收声时，裁剪不得早于收声结束，且切口必须落在静音里」，另加硬起音淡入与全静音段兜底两例。

### 9.4 字幕切分器重写（725 → 717 条）

真实语音时码把两个此前被估算掩盖的断句缺陷暴露了出来，本轮一并修掉：

| 缺陷 | 现象 | 处理 |
| --- | --- | --- |
| 纯标点字幕条 | 切分把 `、`/`，` 单独切成一屏，一闪而过 | 纯标点尾片并回前一条；切分按「CJK 单字 / ASCII 整词 / 标点」原子进行，标点跟随前一个原子 |
| 英文词被拆断 | `Agent` 被切成 `Age` + `nt` | ASCII 连续字母数字视为不可分原子，超宽时只在原子边界折行 |
| 短条一闪 | 单条 < 0.9 s，来不及读 | `MIN_CUE_SEC = 0.9` 作为可读性下限，不足时向同单元上一段借时间 |
