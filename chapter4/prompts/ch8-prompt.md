## 3. 这一章的讲解重点（拍板，别自行发挥）

1. **原文自己声明"面向完全没有强化学习背景的读者"**——这是本章最大的资产，直接继承它：
   每一步先讲**目的**，再讲**原理**，最后才给名词。不要自己发挥去补数学推导，
   原文已经把该打的比方都打好了（通识教育 / 研修专业教材 / 老师示范 / 自己下场做题）。
2. **四阶段地图是全章的骨架，必须在两处出现**：子 A 在 8.1 的开头和结尾各放一次
   （进 8.1 时立图、出 8.1 时回图），你在**本章小结**里再用一页把它回收。
   读者合上 deck 只记得住这一张图，就让他记得住这一张。第一次画和最后一次回收必须完全一致
   （同样的四段、同样的顺序、同样的类比），不许各画各的。
3. **两条主线必须显式点出来，不能只靠读者自己悟**：
   - 主线一：在本章的对照实验里，SFT 更容易记住示范，RL 泛化更好。
     **这是实验条件下的结论，不是 SFT/RL 的普遍属性**——原文专门做了限定，
     这个限定一个字都不能删，删了就是在教读者一个错结论。
   - 主线二：**数据和环境比算法更重要。** 这是全章"最反直觉也最有价值"的一条，
     单独给一页，并把原文那句"很多场景下只要前两类数据质量到位，你甚至根本不需要做 RL"
     原样保留成 `.note`。这句刹车不加，读者会去做完全不必要、也做不动的 RL。
4. **8.9（RL 算法）是最容易变成公式墙的一节**，只给 4 页，其中公式最多占 1 页。
   重点不是推导 PPO/GRPO，而是讲清"为什么要用组内相对优势而不是绝对奖励"这类直觉。
   公式旁边必须有一句人话。**一页里超过两行公式就是排错了。**
5. **8.13 蒸馏对传统开发人员最陌生**，需要一个像样的类比（学生模型学老师模型的输出分布，
   而不是学标准答案），别一句"知识蒸馏"带过。
6. **8.15 后训练实践要点是读者唯一能立刻拿去用的清单。** 34 行给 3 页，不要压成 1 页，
   做成"该做 / 别做"两列对照最好用。
7. **8.2 / 8.3 标了 [可选阅读]，但不许删。** 原文的阅读指引明确说"应用开发者可以跳过"，
   所以处理方式是：**页面保留、篇幅压到 8 页、每页角上标一个「可选阅读」chip**，
   让读者自己决定跳过。删掉的话，模型的训练工程师这条路径就断了。
8. **所有实验结论都要带条件**（什么模型、什么任务、什么预算）。原文大量出现
   "在这些实验条件下"这种限定语，是本章可信度的来源，不许为了页面干净而删掉。

## 4. 硬性约束（第 5 章验证过，别改）

- **只用骨架已有的 CSS 类，不改 CSS / JS。** 微调用行内 `style`，只允许
  `margin` / `padding` / `max-width` / `font-size`。
- 一页一个结论，标题写成一句**能被反驳的话**，不写"强化学习算法"这种目录式标题。
- 卡片正文 ≤3 行，导语 ≤2 行，一页 ≤1 个 `.note`。
- 中文全角括号词组不许跨行断开（整组包 `<span class="nw">` 或手写 `<br>`）。
- 内容块 `max-width` 要么不写（吃满 1124 版心），要么显式对齐，**不许写 1020 这类数**。
- 零外链。四阶段流程图、RL 循环图、奖励设计示意图一律手写 SVG。
- **原文是公式 epub 转出的，`kk` / `nn` / `pp` / `RR` 这类重复字母是渲染残留，
  还原成单个字母。** 公式保留，但旁边必须有人话。
- 中文引号用「」，**不要写脚本批量替换**（会改坏 CSS/JS，见 `references/qa-and-pitfalls.md` 坑 2）。
